---
title: "Color meaning"
description: "Five colors, one meaning each, with a do and a do not from the current product for every rule."
---

Each color carries one meaning, everywhere. A reader who has learned that gold means money and red means "this cannot be undone" can read any screen without a legend. That only works if no screen spends a color on something else.

Values, classes and measured contrast are in the [design token reference](/design/tokens). Neutrals (`--fg`, `--line` and the surfaces) carry no meaning and are used for everything else.

| Color | Token                     | Meaning                                                                                     | Never for                                     |
| ----- | ------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------- |
| Cyan  | `--accent`                | Interactive: something the user can press, follow or select, and the focus ring (`--focus`) | Decoration, status or emphasis on static text |
| Gold  | `--value`                 | Recovered value: XLM amounts and totals the user gets back                                  | Buttons, links, status dots or decoration     |
| Red   | `--danger`, `--danger-fg` | Irreversible actions and errors                                                             | Caution that can still be changed             |
| Amber | `--warning`               | Caution: read this before going on, it can still be changed                                 | Irreversible actions, errors or progress      |
| Green | `--success`               | Confirmed: on the ledger or finished                                                        | Something planned, pending or merely possible |

The examples below are taken from the current product. A "do not" names a place where the product still breaks the rule, kept here so the deviation is on record until it is fixed; where none is left, it states the mistake the rule prevents.

## Cyan is interactive

**Do.** The primary variant of `Button` is a solid cyan fill with `--accent-fg` text (`apps/web/components/ui/button.tsx`). Links and the focus ring are cyan for the same reason: they can be acted on.

**Do not.** Set static text in cyan. A section label cannot be pressed, so it is neutral on every page, and the decorative rule before it uses `--line-strong`. `apps/web/tests/unit/marketing-eyebrow.test.ts` fails on a cyan label or rule.

## Gold is recovered value only

**Do.** On the plan screen, the amount after "You will receive about" is gold, because it is the XLM the user gets back (`apps/web/components/plan/AccountSummaryCard.tsx`). On the landing page headline, "Close the account. Keep the lumens.", only the word "lumens." is gold, because it names the value (`apps/web/app/(marketing)/page.tsx`).

**Do not.** Fill a button or color a link gold, even one that leads to the money, such as "Open the app". A button or link is interactive, so it is cyan, and only one per screen is solid. Every marketing action uses `Button` (`apps/web/components/ui/button.tsx`), and a `no-restricted-syntax` rule in `apps/web/eslint.config.mjs` rejects a gold class on the class name of any button or link in the web app.

## Red is irreversible or error

**Do.** On the execution screen, the button that signs and submits the close, "Sign & execute close", uses the danger variant, a red fill, because the merge cannot be undone (`apps/web/components/execution/ExecutionWizard.tsx`). Error callouts use `--danger-fg` text on the red tint.

**Do not.** Put a statement that something cannot be undone in an amber warning callout. The account entry screen's "Irreversible action." notice is a danger callout for that reason (`apps/web/app/(app)/[network]/page.tsx`).

## Amber is caution

**Do.** On the plan screen, when LumenWipe cannot exit a DeFi position, the notice that says so and asks the user to acknowledge leaving it behind is an amber warning callout (`apps/web/components/plan/LeavePositionAcknowledgement.tsx`). The user can still change course, so it is caution.

**Do not.** Use amber for progress or for a failure. The allowance revoke dialog's header icon is neutral while the user confirms and signs, and red after a failure (`apps/web/components/allowances/RevokeAllowanceModal.tsx`).

## Green is confirmed

**Do.** In the execution sidebar, a step turns green with a check mark only once its transaction is confirmed (`apps/web/components/execution/PlanSidebar.tsx`).

**Do not.** Mark something planned in green. On the plan screen, nothing has been signed or submitted yet, so the "Swap" badge, the swap arrow and the "Recommended" tag are neutral (`apps/web/components/plan/AssetDispositionCard.tsx`, `apps/web/components/ui/decision-card.tsx`). A decision tag has no green tone at all; a planned conversion stays neutral until it is confirmed.

## Text on the marketing pages

Body text on the ink is white at 70 percent or more. Anything dimmer, such as a caption or a source line, uses `--fg-muted` or `--fg-subtle`, the caption floor; `--fg-subtle` measures 6.43:1 on `--bg` and 5.63:1 on `--surface-raised`. A `no-restricted-syntax` rule in `apps/web/eslint.config.mjs` rejects white below 70 percent on the marketing pages, and `apps/web/tests/unit/marketing-contrast.test.ts` fails on any marketing text color under 4.5:1 on the ink or on a card.

## The logo is not a color example

The mark uses cyan and gold together. It is a fixed asset and is never recolored or used as a source of meaning; see [logo usage](/brand/logo).
