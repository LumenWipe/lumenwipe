## Request rate

One budget per API key covers every endpoint on both networks, so a key used for mainnet and testnet spends the same budget. A request without a valid key is counted against its client IP. The service index, `/health` and `/health/deep` are not limited.

Every limited response reports the budget in `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`, and a rejected request is `429 rate_limited` with `Retry-After`. The older `X-RateLimit-*` names carry the same values and are deprecated; see [Compatibility and deprecation](/integrators/compatibility#deprecated-today). The [API reference](/api-reference/introduction#rate-limits) describes the full behavior, including what counts against the budget.

## Keys and sessions

A wallet holds at most the number of active keys above. Creating one more answers `409 key_limit_reached`: revoke a key first.

Signing in to the [API keys page](https://lumenwipe.com/api-keys) signs a one-time challenge, which must be answered within its lifetime, and gives a session that manages keys for the session lifetime above. The session token is not an API key and calls nothing else. An API key itself does not expire; revoke or rotate it on the same page.

## Bodies and batches

A JSON body over the limit is refused with `413 payload_too_large` before it reaches a route. A close never puts more operations in one transaction than the limit above: an account with more to remove is closed over several transactions, and `remaining.requiresAnotherCall` says when another round is needed. `close/batch-plan` refuses more addresses than its limit with `400 too_many_addresses`, and `close/delivered` refuses more hashes than its limit with `400 invalid_tx_hash`.

## Sponsored fees

Where sponsored fees are available (see [Networks](/integrators/networks)), the sponsor pays at most a fixed fee per transaction and stays within a daily budget per network, per source account, per API key and in total. A spent budget answers `429 sponsorship_budget_exhausted` until the next UTC day. The values are in `apps/api/src/config/constants.ts`, and the rule is invariant INV-39 in the [invariant register](/invariants).

## Request a higher limit

A higher request rate is given as a key that carries its own limit and window, issued by the operator. It replaces the default for that key only, and rotating the key keeps it. To ask for one, open an issue in the [GitHub repository](https://github.com/LumenWipe/lumenwipe/issues) with the key's id (never the key itself), the network, and your expected peak rate in requests per minute. The other limits on this page are fixed in the code and are the same for every key.
