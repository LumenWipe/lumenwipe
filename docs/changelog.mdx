The web app has no version number, so entries are dated by the day they were merged. SDK releases are tracked separately: see [SDK versioning](/sdk/versioning). The full history is the repository's commit log.

## Current availability

As of 2026-11-14, the mediator flow (exchange closes) and sponsored fees are available on testnet. Mainnet availability follows the deployment status in the [monitoring plan](/monitoring-plan). FxDAO exits are testnet only. See [Supported](/reference/supported) for the full matrix.

## 2026-11

### 2026-11-09

- **API:** `close/submit` no longer refuses an envelope with no signatures as `invalid_signature`: it sends it, and the network decides. A pre-authorized transaction carries no signatures, so pasting one in the web app now submits it. An envelope short of the account's signing weight is `submit_rejected` with `resultCode` `tx_bad_auth`. A signature that names the source account's key and does not verify is still refused as `invalid_signature` before anything is sent.
- **API:** `GET /` reports `gitSha`, the commit the running service was built from (`null` for a build without one), so which commit is deployed is one request.

### 2026-11-08

- **API:** For an account whose first round is signer normalization and that has Soroban rounds ahead, `close/transactions` no longer counts the normalization round's fee twice when it checks the account can pay its own fees, so it refuses with the same `close_fee_balance_short` amount the `close/plan` blocker reports. For every account whose first round is signer normalization, both also now count the master key the next call still lists once normalization has landed (one base fee more in `close_fee_balance_short`), so an account that holds the reported amount is not refused on that call.
- **API:** With a fee sponsor configured, a close with a transaction the sponsor does not pay for (revoking a sponsorship, or paying an asset to its issuer or to another account) that the account cannot pay itself is now a `close/plan` blocker (`close_fee_balance_short`, with the amount), and `close/transactions` refuses it with the same code and amount before it builds any round. The build now keeps the account's XLM for those fees, and for later rounds, before paying a fee the sponsor would, so an earlier round it can sponsor no longer spends XLM a later one needs.
- **API:** With no fee sponsor configured, the own fees `close/plan` and `close/transactions` reserve up front now include one base reserve, and the two operations that dispose of and remove it, for each trustline a claim round opens. Before, a close short only by that reserve was refused with `close_fee_balance_short` after its claim round had landed.
- **API:** On a network with no fee sponsor configured, a close whose own fees the account cannot pay above its reserve is now a `close/plan` blocker (`close_fee_balance_short`, with the amount to add), and `close/transactions` refuses it with the same code and amount before it builds any round. Before, the plan showed no blocker and the refusal could come after earlier rounds had landed.
- **API:** An exchange close on a network without a configured relay account, or while exchange closes are paused, is now a `close/plan` blocker (`mediator_not_configured` or `exchange_forward_paused`), and `close/transactions` refuses it with the same code before it builds any cleanup transaction. Previously `mediator_not_configured` was returned only after the cleanup transactions had landed.
- **API:** New error codes `exchange_forward_paused`, `fee_sponsorship_paused` and `defi_exit_paused` (all `503`). Each is reported as a `close/plan` blocker and refused by `close/transactions` before any transaction is built; `/mediator/sign` and `/fee-bump/sponsor` also return the first two. A paused Soroban token conversion is reported as `soroban_token_conversion_unavailable`.
- **Docs:** An Integrators section: a [Quickstart](/integrators/quickstart) from an API key to a verified testnet close, a [Networks](/integrators/networks) page with what differs between mainnet and testnet and a mainnet go-live checklist, one [Limits](/integrators/limits) page generated from the code, and a [compatibility and deprecation policy](/integrators/compatibility) with a minimum 6-month deprecation window and the checklist that defines SDK 1.0.
- **API:** The deprecated `X-RateLimit-*` response headers are not removed before 2027-06-01.

### 2026-11-07

- **Web:** The receipt page has a "Print or save as PDF" action. The printed receipt is black on white, with the full destination and every transaction hash and explorer URL in full, the details of each group open, and no navigation, buttons or background.
- **Web:** A receipt can be copied as a plain-text summary or downloaded as JSON or CSV, from the receipt page and from each history entry. The files are made in the browser from the saved receipt and follow the documented [receipt format](/reference/receipt-format), with values that were not recorded marked as such and CSV cells neutralised against spreadsheet formulas.
- **Web:** The receipt has one primary action, viewing the destination on Stellar Expert, with StellarView as a text link and "Close another account" as the secondary; the actions stack on narrow screens. Explorer links say what they open and that they open a new tab. Addresses and hashes are shortened by default and can be shown in full and copied, and the "what was done" groups open and close behind a count. A reopened receipt announces its outcome and focuses its heading.
- **Web:** A closed receipt leads with the XLM the destination received, read from the merge's ledger result through `close/delivered`, and the full destination with a copy button. An amount that cannot be read says so with the transaction hashes to check on the explorer; it is never shown as zero. Once read, the amount is kept in the saved receipt, so reopening it asks nothing.
- **API:** `GET /v1/{network}/close/delivered` reports the XLM confirmed close transactions delivered to their destination, read from each transaction's ledger result: the merged balance, or the relay account's forward for an exchange close. A transaction that is unknown, failed, or delivered nothing this way is marked unavailable, and the total is present only when every transaction resolved.

### 2026-11-02

- **Web:** Analyzing an account reads it once. Answering a claimable-balance card or acknowledging a position updates the plan without reading the account again, and an unknown account now reports on the analyze page.
- **Web:** The `paths` proxy route is no longer cached. `docs/architecture.md` lists every cached route with its time to live.
- **API:** `submit_rejected` is now `422` instead of `502`, so a transaction the network refused no longer reads as an API outage. `502` and `504` stay reserved for upstream faults. Anything branching on the status has to move to the code or the new status.
- **API:** `mediator_key_misconfiguration` is now `503` with `Retry-After` and a neutral message instead of `500`.
- **API:** `submit` reads by hash before it reports a failure and answers within 35 seconds. When no verdict arrives, `confirmation_timeout` carries `details.status` set to `pending` and `details.hash`.
- **API:** `GET /v1/{network}/transactions/{hash}` looks a transaction up without submitting anything, and `GET /v1/{network}/close/status` reports a close's phase and remaining work from live state.
- **Web:** a timed-out or interrupted submit no longer shows an error. The app sends the same signed transaction again a bounded number of times, then shows the hash and a check action, and a close counts as finished only when the hash computed from the signed merge is confirmed.
- **Web:** a proxy with no API configuration answers `503` with `Retry-After` instead of `500` or `502`.

## 2026-10

### 2026-10-11

- **API:** an asset with no swap route no longer defaults to a return to its issuer. The decision has an empty default and needs an explicit answer. A failed route lookup is a retryable `route_lookup_unavailable` blocker, and a balance too small to swap is reported as such.
- **Web:** a balance too small to swap has its own card, and a stored return-to-issuer choice is dropped when a re-analyze cannot confirm routes.

### 2026-10-10

- **Web:** the shared exchange account is called the relay account in the app, replacing a mix of "mediator" and "intermediary". The API and these docs keep "mediator".
- **Web:** terminal close states report what actually happened, and signing progress and failures are announced to assistive technology without moving focus.
- **API:** every response reports the rate limit budget in `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`, plus `Retry-After` when a request is rejected. The older `X-RateLimit-*` names are deprecated.
- **API:** error responses carry a documented error code, and bad request bodies are answered with a 4xx in the standard error envelope.
- **Registry:** the contract and exchange registries were re-verified.

### 2026-10-07

- **Registry:** the retired Aquarius concentrated pool code was dropped from the registry.

### 2026-10-02

- **Web:** a self-service page to create an API key.
- **SDK:** a headless testnet close example.
