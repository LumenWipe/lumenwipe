The architecture and the [threat model](/threat-model) state several invariants in prose. This page lists each
one with the code that enforces it and the test or CI job that would fail if it stopped being true, so a reader
can tell which claims are tested, which rest on a lint rule, and which are design intent with no test yet.

**Status as of 2026-10-13, checked against commit `5d661ed`.** `bun run check:docs` fails the build when a file,
symbol or test named below no longer exists, so a row cannot quietly point at code that has moved. It does not
prove that a test still asserts what the row says; that stays a review question.

## How to read a row

- **Enforced by** names a file and, after `#`, the symbol in it that holds the rule.
- **Proved by** names a test file and, after `#`, the exact test name, or a CI job in
  `.github/workflows/ci.yml`.
- **Status** is one of:
  - **Enforced**: a test or CI job fails if the rule breaks.
  - **Enforced, with a residual**: the rule is tested, but it is narrower than the prose elsewhere; the residual
    is linked.
  - **Design intent**: the code is written this way, but no test or job would catch a change.

## Keeping this page true

A new close operation, signing key, adapter or boundary adds or changes its row here in the same pull request,
next to its STRIDE entry ([threat model, Section 13](/threat-model#13-maintenance)). Run `bun run check:docs`
before pushing; CI runs it on every pull request.
