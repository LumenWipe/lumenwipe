## Destinations

| Destination | How it is closed to                                                                                                        | Network                                                     | Verified   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ---------- |
| Wallet      | A single `ACCOUNT_MERGE` into the destination account                                                                      | Mainnet and testnet                                         | 2026-10-10 |
| Exchange    | A merge into the mediator (the relay account), then a payment from it to the exchange address you typed, with the memo     | Testnet today, see [availability](#availability-by-network) | 2026-10-10 |
| Anchor      | Not a distinct destination type. There is no anchor-specific handling: an anchor address is treated as an ordinary account | Mainnet and testnet                                         | 2026-10-10 |

Every listed address requires a memo (memo types in the registry: id, text). Last verified 2026-10-10, valid until 2027-01-08.

## Signer types

| Signer                     | How it signs                                                                                | Network             | Verified   |
| -------------------------- | ------------------------------------------------------------------------------------------- | ------------------- | ---------- |
| Wallet                     | The wallet signs the unsigned transaction and returns it                                    | Mainnet and testnet | 2026-10-10 |
| Secret key                 | Held in memory for the session only                                                         | Mainnet and testnet | 2026-10-10 |
| Several signers (multisig) | Signatures accumulate on the same transaction until the threshold is met                    | Mainnet and testnet | 2026-10-10 |
| hash(x) signer             | You enter the preimage, and the app checks it hashes to the signer key before using it      | Mainnet and testnet | 2026-10-10 |
| Pre-authorized transaction | Only by pasting the exact pre-authorized transaction, which the app does not verify for you | Mainnet and testnet | 2026-10-10 |

See [Signing options](/guides/signing-options).

No automated test signs through a real wallet, so a wallet appearing here means the app offers it, not that every release was exercised against it. Per-wallet network support is not tested; the app passes the active network passphrase to the wallet.

## Limits

Verified 2026-10-10 against the code named in each row. Rate limit state is reported on every response in the `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset` headers, with `Retry-After` on a rejected request. The older `X-RateLimit-*` names are still sent and are deprecated. See the [API reference](/api-reference/introduction#rate-limits) for the full behavior.

{/* generated:limits:start */}

| Limit                            | Value                                    | Where it is enforced                                                                                                                      |
| -------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Operations per transaction       | 100                                      | `OP_BATCH_LIMIT` in `apps/api/src/config/constants.ts`                                                                                    |
| Addresses per batch plan request | 20                                       | `BATCH_PLAN_MAX_ADDRESSES` in `apps/api/src/lib/close-api/batch-plan.ts`                                                                  |
| JSON request body                | 100 KB                                   | `JSON_BODY_LIMIT` in `apps/api/src/configure-app.ts`                                                                                      |
| Default request rate             | 120 requests per 60 seconds, per API key | `THROTTLE_LIMIT` and `THROTTLE_TTL` defaults in `apps/api/src/app.module.ts`, overridable per deployment, and per key for self-serve keys |

{/* generated:limits:end */}
