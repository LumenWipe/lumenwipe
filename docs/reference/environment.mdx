Each app reads its own `.env.local`, copied from the `.env.example` next to it: `apps/api`, `apps/web` and `apps/playground`. The table below is generated from those three files by `bun scripts/supported-matrix.ts --write`, and a test fails when an example lists a variable this page lacks, or the page lists one the examples dropped.

**Required** is `Yes` when the app refuses to start or cannot serve its purpose without the variable, `Production` when only a production deployment needs it, and `Tests only` when only the funded integration tests read it. A **Secret** value never goes in source control or a `NEXT_PUBLIC_` variable, which the web build inlines into the browser bundle. The defaults are the values the code falls back to when the variable is unset.

The API still reads the `NEXT_PUBLIC_`-prefixed names of its endpoint and mediator variables (for example `NEXT_PUBLIC_STELLAR_RPC_TESTNET`) as a fallback, with a startup warning. Use the names below.

For local development, the API needs only `API_KEYS` to start, and the web needs `LUMENWIPE_API_KEY` set to one of those keys: see the [contributor setup](https://github.com/LumenWipe/lumenwipe/blob/main/CONTRIBUTING.md#3-development-setup). Account reads also need `PATH_ROUTING_API_TESTNET`, a Horizon-compatible endpoint such as `https://horizon-testnet.stellar.org`.
